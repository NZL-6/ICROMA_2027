# Computational environment

The reported experiment used Windows x64 and Python 3.12.3 (conda-forge build). The source code is packaged with relative paths, but the complete pipeline has not been rerun on another operating system. Windows x64/Python 3.12 is the closest documented reproduction platform. The CPU PyTorch wheel listed here is available for Windows and Linux; other platforms need a separately documented environment adaptation.

Two numerical stacks are intentional. Feature analysis and learning used NumPy 1.26.4 and pandas 2.2.2 in the main Python environment. Solver processes prepended a separate dependency directory containing OR-Tools 9.15.6755, NumPy 2.2.6 and pandas 2.2.3. Installing all requirements into one environment would change the measured software configuration.

Use `requirements-learning.txt` in a Python 3.12 virtual environment, then install the five solver distributions with `--no-deps --target .solver_deps -r environment/requirements-solver.txt`. Shared solver dependencies such as `absl-py` are provided by the main environment. OR-Tools 9.15.6755 is published on PyPI, including a CPython 3.12 Windows x64 wheel; the retrieved wheel URL and SHA-256 are recorded in `distribution_sources.json`.

One historical metadata inconsistency is preserved explicitly: OR-Tools declares `typing-extensions>=4.12`, whereas the archived main environment had 4.11.0 and no solver-local override. The published results were generated with that installed combination. The exact archived recipe therefore uses `--no-deps`; it is not claimed to satisfy all current package metadata. To satisfy OR-Tools' declaration without changing the learning environment, optionally install `requirements-solver-compatibility.txt` into `.solver_deps` with `--no-deps`. That solver-only 4.12.2 overlay is a documented compatibility change, not the historical environment. The verifier reports whether it is present.

Only package metadata, source syntax, and data integrity were checked while preparing this release. No training or optimization was repeated. Package versions are pinned; installation of the complete environment and a full run remain untested in a clean machine. Parallel CP-SAT search and hardware scheduling can change accepted representatives and wall times even with the same seed. The archived result tables are the reference for the numbers reported in the manuscript.
